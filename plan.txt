# Local LLM Server — Architecture & Decisions
# This file: project-internal technical reference
# See README.md for user-facing quick-start

═══════════════════════════════════════════════════════════════
 OVERVIEW
═══════════════════════════════════════════════════════════════

Goal: Run a local Qwen model on this machine and expose it securely
      over the LAN as an OpenAI-compatible API for use by opencode
      (or any compatible client) in an LXD container.

Host hardware:
  CPU   : AMD Ryzen AI 9 HX 370 (12c/24t)
  RAM   : 62 GB
  GPU   : Radeon 890M iGPU (Vulkan ✓, shares system RAM)
  Disk  : ~186 GB free

═══════════════════════════════════════════════════════════════
 INFERENCE ENGINE
═══════════════════════════════════════════════════════════════

Backend: llama-server (llama.cpp), compiled with -DGGML_VULKAN=ON

  - Direct llama.cpp HTTP server; no wrapper overhead
  - OpenAI-compatible REST API at http://127.0.0.1:{server_port}
  - Full control over --n-gpu-layers, --threads, --batch-size, --ctx-size
  - Vulkan backend offloads layers to Radeon 890M iGPU

Why not Ollama? Ollama wraps llama.cpp and hides tuning knobs. Direct
llama-server gives the same models and API with better performance.
Why not vLLM/tabbyAPI? Both require a discrete CUDA/ROCm GPU.

═══════════════════════════════════════════════════════════════
 TOOLING
═══════════════════════════════════════════════════════════════

Language   : Python 3.12+
Packaging  : uv  (dependency management, virtual envs, running)
Linting    : ruff  (format + lint)
Type check : ty  (Astral's fast type checker)
CLI        : Typer  (type-annotation-driven, works well with ty)

Single entry point:  uv run llm <subcommand>

Subcommand groups:
  llm server    start | stop | restart | status | logs
  llm model     download <hf-repo> [--file x.gguf] | list | switch <name>
  llm benchmark run [--prompt x] [--n-tokens 200] | history
  llm client    setup         # prints export commands for LXD container
  llm config    init | show | apply
                init  — generate config.toml with commented examples
                show  — print current settings
                apply — render nginx/systemd templates with real values

═══════════════════════════════════════════════════════════════
 CONFIGURATION (config.toml — gitignored)
═══════════════════════════════════════════════════════════════

Single TOML file. Never committed. Run `llm config init` to create it;
the generated file includes every option as a commented example so it
serves as its own documentation.

[server]
  llama_server_bin  Path to llama-server binary
  port              Internal port (default: 8080)
  n_gpu_layers      Vulkan iGPU layer offload count
  n_ctx             Context window size
  n_threads         CPU threads for inference
  extra_args        List of extra llama-server flags

[models]
  dir               Directory containing GGUF files
  active            Filename of currently active model
  hf_token          HuggingFace token (for gated models) <- never commit

[proxy]
  port              nginx external port (default: 8443)
  lan_ip            This machine's LAN IP                <- never commit
  lan_subnet        Allowed source subnet (e.g. 192.168.1.0/24) <- never commit
  api_key           Bearer token for clients             <- never commit

═══════════════════════════════════════════════════════════════
 SECRETS & PUBLIC REPO SAFETY
═══════════════════════════════════════════════════════════════

config.toml                          <- gitignored; real values + commented examples
nginx/llm-proxy.conf                 <- gitignored; rendered output
systemd/llm-server.service           <- gitignored; rendered output
logs/                                <- gitignored

nginx/llm-proxy.conf.template        <- committed; {{VAR}} placeholders
systemd/llm-server.service.template  <- committed; {{VAR}} placeholders

`llm config apply` renders the templates using values from config.toml.
Nothing with a real IP, subnet, or secret is ever committed.

═══════════════════════════════════════════════════════════════
 MODEL RECOMMENDATIONS
═══════════════════════════════════════════════════════════════

With 62 GB RAM this machine can run models most systems cannot.
GGUF format, downloaded via huggingface-hub.

  Fast / light:
    Qwen2.5-Coder-7B-Instruct-Q8_0         ~8 GB   best for quick tasks
    Qwen2.5-Coder-14B-Instruct-Q4_K_M      ~8.5 GB good balance

  High quality:
    Qwen2.5-Coder-32B-Instruct-Q4_K_M      ~18 GB  strong coding model
    Qwen2.5-Coder-32B-Instruct-Q8_0        ~34 GB  high precision 32B

  Maximum quality (62 GB advantage):
    Qwen2.5-72B-Instruct-Q4_K_M            ~42 GB  near-frontier quality
    Qwen2.5-Coder-32B + large ctx          ~18 GB model + ctx overhead

  Efficient MoE:
    Qwen3-30B-A3B-Q4_K_M                   ~17 GB  30B param, 3B active

Default: Qwen2.5-Coder-14B-Instruct-Q4_K_M (speed/quality/size balance)
Upgrade path: switch to Qwen2.5-72B-Instruct-Q4_K_M for best results

═══════════════════════════════════════════════════════════════
 NETWORK & SECURITY
═══════════════════════════════════════════════════════════════

nginx reverse proxy:
  - Listens on {lan_ip}:{proxy_port} (HTTPS, self-signed cert)
  - Auth          : Bearer token ({api_key})
  - IP allowlist  : {lan_subnet} only
  - Forwards to   : http://127.0.0.1:{server_port}

systemd: auto-starts on boot, restarts on crash, logs to journald
LXD container on client: additional isolation boundary

═══════════════════════════════════════════════════════════════
 BENCHMARKING
═══════════════════════════════════════════════════════════════

llm benchmark run:
  Sends prompt to API, measures wall-clock time, parses
  usage.completion_tokens, reports pp + tg tokens/sec.
  Also invokes llama-bench binary (if found) for raw throughput.

llm benchmark history:
  Displays logs/benchmark-history.csv as a formatted table.
  Columns: timestamp, model, pp_tps, tg_tps, ctx, n_tokens, n_gpu_layers

═══════════════════════════════════════════════════════════════
 DECISIONS LOG
═══════════════════════════════════════════════════════════════

llama-server only (no Ollama):
  Ollama is a convenience wrapper around llama.cpp. Direct llama-server
  is faster, exposes all tuning parameters, and model management is
  handled by the Python CLI anyway.

TOML over env file:
  TOML is structured (sections, typed values, inline comments), more
  readable, and parsed natively by Python's tomllib. env files are flat
  and untyped. Single gitignored config.toml with commented examples
  makes a separate example file unnecessary.

llm config init generates a self-documenting config:
  Generates config.toml with every option commented out showing example
  values and descriptions — no separate example file needed.

Python over shell scripts:
  Type safety (ty), linting (ruff), testability, and Typer gives a
  polished --help experience for free.

uv over pip/poetry:
  Significantly faster; handles venvs + lockfiles; `uv run` means no
  manual venv activation.

Typer over Click/argparse:
  Derives CLI from type annotations — works perfectly with ty.

Vulkan over ROCm:
  ROCm 6.x has poor iGPU support. Vulkan is stable on the 890M.
